# 安全模型

## 窗口外壳操作

主窗口为公共标题栏菜单增加原生调整大小和置顶能力。操作只定位当前窗口，关闭继续经过既有未保存内容保护。不新增应用命令、文件访问、网络来源、HTML 渲染或终端输入。

## 外部会话目录与图片

只读命令 `acp_workspace_root` 返回应用拥有的默认工作区路径并准备该目录，不接受调用方提供的路径。没有显式项目目录的会话在各自的新文件夹中启动，避免意外继承项目，但不对外部进程实施文件系统沙箱。附件复用现有选择、拖放授权和应用附件存储。图片提示要求代理声明对应能力，并限制图片块及出站消息大小；入站和重放上限不变。关闭或取消会话会使未完成的附件读取失效，读取失败保留输入草稿。没有新增能力、内容源、任意读取或授权。

ACP 对话本地留存新增四个应用数据库命令，分别负责保存、列举、读取和删除。存储由应用拥有的 SQLite 承担：最多 200 条、单条对话 16 MiB、元数据有界、可识别凭据会被脱敏，列举路径只返回元数据。它不授予文件、进程或网络权限；内置对话记录本就跨越同一渲染器／数据库边界。没有放宽能力、CSP 来源或路径范围。数据库往返、脱敏、裁剪与重载测试覆盖该边界。

## 外部执行上下文

外部工具初始化与描述说明代理宿主和显式选择的应用终端之间的区别。终端读取成功时返回本轮捕获的有界主机、目录、解释器与用户备注，仅复制主机、用户名及端口元数据，不包含认证字段。备注仍是不可信上下文，不授予权限。未选择目标和远端误用本地文件工具分别返回对应说明，不会自动选择终端、建立另一连接或更改工具权限。原生授权、捕获目标归属及诊断脱敏保持不变；不增加 IPC 命令、能力或内容源。

## 对话轮次与传输上限

本地工具按轮次共用串行执行控制。拒绝或未回答的问题关闭该轮排队及后续调用，新的用户消息使用新的范围；原生策略、确认及执行租约仍然生效。外部协议消息与重放缓冲具有显式大小限制，队列有界；等待响应期间持续消费重放。轮次结束排在已接收内容之后，历史加载失败的部分正文不能进入替代会话。请求标识保留原有类型。这些变更不增加命令、能力、文件授权或网络来源；外部程序独立配置的工具仍不受该适配层控制。

## 正式版签名更新

仅主窗口获得检查、下载、安装和重启能力。平台适配层使用固定的 HTTPS 发布源与项目链接，用户输入不能提供更新地址或公钥。原生更新器使用内置公钥校验下载包，通过后才允许安装。版本说明以有长度上限的纯文本渲染；即使发布源返回测试版，也会拒绝。启动时不会自动检查、下载或安装。

安装先经过明确确认与现有未保存文档保护，再关闭终端会话、刷新诊断并调用原生安装；重启失败后的重试不会重复安装。签名私钥位于仓库及渲染进程之外，在本机限制访问，仅通过加密的仓库密钥提供给发布任务。手动发布工作流校验正式版本号一致性，在四个平台的签名条目齐全前保留草稿，拒绝覆盖已发布版本，只有显式选择才发布。不增加文件授权或渲染内容来源。更新与进程能力属于主窗口的高权限能力，仍依赖现有内容隔离。

本地记忆按范围、有效期保存并有限检索，旧文件保持待确认，不会整份进入提示词。共享界面的特权操作在分发入口消费一次性租约，界面租约绑定原生 webview 和完整参数，专用工具租约保留原授权流程。工具名与目标命令必须对应，完整工具结果和租约不进入诊断。不增加网络服务、模型、能力或 CSP 来源。主渲染进程仍属于信任边界：界面租约不证明物理用户手势，也不能隔离同一 webview 内的代码。生命周期与剩余边界见本文第 5 节。

对话流按独立归属标识、取消控制器、队列与审批范围并发运行，既有终端忙碌保护继续拒绝冲突命令。模型代理仅把建立请求阶段的失败标为可能重试；客户端不重放已开始的响应或整个工具轮次。重试保留相同的已校验端点与凭据路径，等待有上限且可取消，不增加应用命令或能力权限。

空启动窗格在布局元数据中使用经过校验的布尔标记。用户明确恢复历史时，沿用原资源所有者重建空窗格，不恢复命令，也不重建缺失的非空对话内容。远程空窗格要求存在原保存连接，仍经过标准认证路径，不改变凭据、能力或执行策略。

## 绑定前台目标的终端粘贴

剪贴板文字、原生粘贴事件和图片粘贴按键在读取剪贴板及等待确认期间保留原会话、终端界面、运行块和输入模式。文字仍由现有终端解析器编码。粘贴携带原生输入轮次：命令／提示符标记和备用屏幕切换会在输出合批前使旧轮次失效；发送前，界面核对最近观察到的轮次与后端状态。队列每段检查目标，后端取得写锁后和每次有界部分写入之间再次检查；换行按键与前面的文字分开发送。前台结束会取消排队输入，不把尾部重放到命令输入框或新提示符。诊断只记录取消元数据。

`pty_input_epoch` 仅读取已有会话的计数，不增加执行、文件或网络权限；`pty_write` 的可选轮次参数只会收紧已有写入。普通键盘输入沿用现有授权。单元测试、原生部分写入测试和浏览器测试覆盖运行块、手动全屏及备用屏幕应用在粘贴中退出，以及过期确认和延迟剪贴板结果。

这属于基于已观察输入边界的取消，不是进程隔离。系统终端输入缓冲区已接收的字节无法撤回；不提供受支持生命周期标记的程序或 shell 也无法提供同等边界证据。括号粘贴协议本身不是应用已消费文本的确认，测试不能宣称已接收字节绝不会到达后续读取者。

## 会话专属应用工具

内部工具适配层使用带认证的临时回环分帧连接及标准输入／输出辅助进程，令牌仅在子进程环境中传递。每个外部连接独立维护工具白名单、活动轮次和待处理结果标识，初始化及历史重放不能执行工具。只有主窗口能答复 `acp_app_tool_result`，结果受大小限制并关联活动请求。现有工具实现继续经过后端策略、路径授权、系统确认及一次性租约。终端目标明确选择并在轮次内固定，远程目标不能调用本地文件工具。取消会清理审批和问题，迟到的批准不能执行。不暴露凭据、任意应用命令分发、公网监听或新内容来源。边界与测试见 `application-tools.md`。

> 读者：**在 Vrykell 上加任何新功能前先读这一页**，尤其是接入第三方代码（MCP 服务器、技能、外部 harness）和新增 IPC 命令的时候。
> 配套文档：`application-tools.md`（会话工具边界）、`architecture.md`（分层）。
> 最近更新 2026-10-30。

## 引用型组合与工具恢复

同一请求中的终端命令在授权与 PTY 写入前按提交顺序串行执行。命令被拒、取消或未确认完成时，后续排队命令不能继续写入；未确认完成的软阻断只在该终端重新确认就绪后对新提交的命令解除，已排队的命令仍然保持阻断；已完成的非零诊断结果不阻塞队列。原有忙碌保护仍防范人工及独立调用方的冲突，取消等待不会终止正在运行的进程。

`save_workspace_history` 只接受有大小限制、版本标识与成员字段白名单的布局引用；拒绝带内容的载荷、非法布局及覆盖终端记录的请求。写入为原子的历史元数据，不是启动进程记录。增量迁移保留现有数据，来源与分屏筛选使用写入时维护的索引标记。`get_conversation` 校验标识，使用绑定参数只查询一条元数据，不加载消息。两条命令均不扩大文件访问、网络来源、能力、CSP 或执行权限。

AI 工具被拒绝后，本轮关闭全部工具，包括继续提问；说明一次结果并结束回复，新的用户消息使用新的恢复范围。系统确认与授权租约仍然必需；换解释器或编码不代表获得权限。窗口失焦不再跳过或直接拒绝系统确认；无人应答仍会超时拒绝，迟到的批准不能执行。远程工具上下文在执行时也拒绝访问本地文件系统。工具错误和审批结果保存在对话中，不自动发布通知。主动查看结果时在工具卡内展开原因和已存输出，不在工具卡底部显示错误。只有已注册的工具可被调用；策略禁用的工具会在提示中列名，模型调用不可用工具时显示内联提示而不是错误卡。终端状态区分忙碌、就绪、交互与未知，安静画面不能作为完成依据，保留的迟到完成标记可以。诊断仍不记录命令、输出及凭据。

`ask_user` 是有长度限制的内存交互，不是特权执行或审批。每轮最多打开一个问题；回答后从后续工具选项移除提问，重复或换句话说都不能再次打开问题卡。跳过或取消的问题结束工具续执行。请求绑定会话和调用，可以取消并在十五分钟后超时。回答不会创建授权，待处理回调不持久化。被隐藏的工具控制标记绝不执行。本功能不增加 IPC、文件系统或网络权限。

## 1. 威胁模型：谁能影响什么

外部结构化提问只在原生处理器存在时声明表单能力。表单绑定接收连接与其当前代理会话；不支持的初始化作用域与 URL 请求直接拒绝。模式、字段、选项、待回答数量及回答大小均有上限；原生端保留回答类型并校验必填项、约束与未知字段，拒绝凭据字段，使用有界线性时间引擎处理模式。回答只能提交一次；超时、停止、关闭和传输中断会释放等待状态。回答不产生执行授权。诊断仅记录生命周期标识与状态，不记录模式、问题和回答。

外部子进程优先采用代理程序显式配置的代理，其次继承进程代理，最后在 Windows 上回退到已启用的手动系统代理。本地桥接主机始终绕过代理。环境更改仅作用于子进程，不记录凭据与代理 URL。此回退不会执行自动代理脚本。

| 输入来源 | 信任级别 | 它能碰到什么 |
| --- | --- | --- |
| 用户本人（键盘、面板、设置） | 权威 | 一切（终端就是任意代码执行，这是产品） |
| **模型输出**（本机 agent） | **不可信内容** | 渲染路径（Markdown）、工具参数（受审批与租约约束） |
| **抓取的网页 / 搜索摘要 / 技能文本 / MCP 工具结果** | **不可信内容** | 同上；也是**提示注入**的入口（内容里可以写"请把 X 发到 Y"） |
| **远程 SSH 主机** | **不可信内容** | 终端输出、远端文件名；会话记录会落库并再次渲染 |
| **第三方 harness（ACP，已接入）** | **用户添加的可执行程序** | 它自己的进程权限（拦不住）；经我们声明的能力发起的操作（可拦） |
| **被完全攻陷的渲染进程** | 最坏情况 | 一切 UI 能做的事——**包括往 PTY 里敲命令**（见 §3） |

一句话：我们保护的是「**不可信内容不得变成渲染层或执行层的指令**」，以及「**危险操作必须经过不可伪造的确认**」。我们不假装能保护「渲染进程本身」和「用户自己装的程序」。

## 2. 安全防线（现状 + 证据 + 验证方式）

| 防线 | 现状 | 证据 | 怎么验证 |
| --- | --- | --- | --- |
| 渲染进程不进 Node | ✅ Tauri 天然无 Node；渲染进程没有直接文件系统权限，一切经 IPC | `src-tauri/tauri.conf.json` | 结构使然 |
| 显式 IPC + 能力清单 | ✅ 只用 `core:default` + dialog/drag/clipboard/opener + 窗口控制；自有命令以注册表为准 | `src-tauri/capabilities/default.json` | 改能力清单需同步文档 |
| 命令级授权（租约） | ✅ 4 个受门控命令（`read_file_text`/`write_file_text`/`edit_file_text`/`fs_search`）必须出示**与命令+参数摘要绑定的一次性租约**，否则失败关闭 | `src-tauri/src/agent/permissions.rs` | `cargo test --lib` 的租约用例 |
| 危险操作不可代答确认 | ✅ 危险命令/凭据路径/持久化写入命中即弹**系统原生对话框**；窗口失焦仍显示确认，不自动拒绝；审批卡有超时 | 同上 + `agent/permissions.rs` | cargo 单测 + e2e `approval-timeout` |
| 授权粒度 | ✅ 等级表（允许/询问/禁止）+ **形态级会话授权**（`npm run` 只放开这一类）+ 危险规则在授予之前判定 | 同上 | cargo 形态派生用例 + e2e `approval-shape` |
| 路径授权（任意读收口） | ✅ 会把文件内容交给页面的命令（附件导入）只接受**系统级用户动作**产生的路径：Rust 侧授权登记表（`files/grants.rs`，持久化在 `~/.vrykell/approved-paths.json`）；选择器改由我们的 `pick_path` 打开（只有 Rust 亲自打开才知道选择来自用户），窗口拖放由 `WindowEvent::DragDrop` 登记；应用自有目录（附件、技能）无需手势；无人调用的 `read_image_data_url` 已删除 | `files/grants.rs`、`lib.rs` | cargo 单测（授权文件/目录/自有目录/未授权拒绝） |
| 内容渲染消毒 | ✅ Markdown 不启用 raw HTML、裸 URL 不 linkify、远程图片降级为文本、链接不导航应用窗口（外链交系统浏览器）；终端/命令块与 SSH 画面快照全部过 `sanitizeOutputHtml`（白名单只有 `<span>`+安全 style+`<br>`，且把"本地 DB 被篡改"写进威胁模型） | `Markdown.tsx`、`sanitizeHtml.ts`、`TerminalPanel.tsx` | vitest（Markdown 链接、快照消毒）+ e2e `chat-links` |
| CSP 与资源范围 | ✅ 生产 CSP：`default-src 'self'`、`script-src 'self'`（Tauri 自注入脚本走 hash）、`style-src 'self' 'unsafe-inline'`（React 内联样式需要）、`object-src 'none'`、`form-action 'none'`、`frame-ancestors 'none'`、img 只允许 self/data/asset、connect 只允许 ipc；dev 例外（HMR 的 ws 与内联脚本）只在 `devCsp` | `src-tauri/tauri.conf.json` | `npm run build` 后确认 `dist/index.html` 无内联脚本；改动 CSP 需重启应用 |
| 密钥与凭据 | 存储方式因平台而异：macOS 使用系统凭据库，Windows 使用绑定当前用户的加密，Linux 及其他平台使用**明文** `~/.vrykell/secrets.json`，目录权限为 `0700`、文件权限为 `0600`。文件权限不等于加密。**模型请求走 Rust 代理，已保存的密钥不返回渲染进程**；附件读取锁死在附件目录。不要同步或分享明文凭据文件。 | `secret.rs`、`files/fs.rs` | 原生凭据测试；检查存储权限并确认 `config.json` 无 key |

## 3. 两条「做不到」，必须写清楚

1. **真隔离不可达**：UI 必须驱动 PTY（终端就是产品），渲染进程一旦失陷就等于用户的任意命令执行，任何 IPC 拆分/把 agent 移出 webview 都改变不了这一点。因此我们的目标是**缩小失陷后的收益**，不是挡住失陷本身。
2. **「调用者身份」这一维现在是空的**：`agent` 与 `UI` 都是同一个 webview 里的 JS，后端无法区分。技术上可行（Tauri 会把调用者 webview 注入命令签名，页面无法伪造），但**只有一个 webview 时做了等于没做**。等引入第二个 webview（例如 ACP harness 的会话 UI）时，同批做：命令命名空间 + 按调用者鉴权 + 租约绑定 `webview_label`。

## 4. 新功能自查清单（每个 PR 都要能回答）

1. **新 IPC 命令**：是否受租约/策略门控？加进受门控命令清单了吗？会不会成为"任意路径读/写/执行"的新入口？
2. **新渲染路径**：是不是又往 DOM 里塞 `innerHTML`？能不能走 Markdown/文本？必须塞 HTML 时过 `sanitizeOutputHtml` 吗？
3. **新内容来源**（第三方文本/文件/接口）：它算不可信内容吗？进渲染层前消毒了吗？会不会诱发一次外链点击？（链接一律走 `Link`，外链默认交系统浏览器）
4. **新能力或新资源**：CSP 需要放宽吗？`assetProtocol` scope 需要扩大吗？能力清单要加吗？——三问都要写进 PR 说明。
5. **新第三方代码**（进程、脚本、插件）：是否由用户显式添加？设置页是否写清"添加即授权"？
6. **新授权**：是否复用现有审批链（等级表 + 形态授权 + 超时 + 危险规则），还是自造了一套？自造的一律需要评审。
7. **日志**：新写日志是否泄漏命令文本/输出/密钥？（诊断日志只记元数据）
8. **测试**：这条防线有没有对应的单测/e2e？（见 §2 最后一列）

## 5. 已知缺口与成本

| 缺口 | 成本 |

## 已保存连接的扩展

工作区统一底层：窗格迁移和删除接受长度受限且互不重复的标识，最多四个窗格引用。迁移要求已有终端会话所有者，并在数据库事务中执行；SQL 值使用绑定参数。删除只针对所选窗格内容，包括映射的旧版主窗格记录。快照在恢复前验证区域、分组、树形/数量、比例和引用唯一性；解析本身不启动进程或文件操作。资源适配复用现有关闭守卫和进程清理。不增加文件授权、能力、网络来源、HTML 解释或审批路径。边界由事务、异常输入、兄弟窗格保留和活宿主测试覆盖。

独立端口转发新增三个显式生命周期命令：启动仅接受已保存连接和规则的标识符，停止定位同一标识符对，状态仅返回运行元数据。后端重新读取并校验已保存端点，复用现有认证、代理和严格主机密钥检查；渲染层不能传入 shell 文本或凭据参数。默认绑定回环地址；用户选择公开监听地址后，对应网络可以访问端点，因此自动启动保留为每条规则的显式偏好。会话数、客户端数、协议握手与缓冲区均有限制。停止、端点修改、主机删除和退出应用会关闭受管监听。不会扩大 CSP、能力或路径范围，也不新增 HTML 渲染或诊断内容。

代理配置命令校验配置标识符、地址语法、端口范围和凭据大小。非敏感配置以原子方式保存；密码保留在现有平台凭据存储中，不包含在返回对象内。终端辅助进程使用经过校验的配置标识符，不在命令参数中携带凭据。HTTP CONNECT 和 SOCKS5 的协议头、地址和握手时长均受限，目标主机密钥验证保持不变。这些协议不加密初始代理认证交换，请在受保护网络中使用可信代理。

远程环境变量作为会话选项发送，不写入本地进程环境。界面和后端分别校验名称、大小、数量与控制字符。备注是具有字节上限的用户上下文，不是策略或授权；诊断记录脱敏环境变量内容及两种备注。本次不扩大能力权限或 CSP 来源。协议、参数、序列化和数据库往返测试与完整页面编辑测试同步提供。支持组合及限制见 `ssh-profiles.md`。

## 端点迁移与文本操作

现有凭据写入命令可将已配置端点的密钥复制到同一 API 类型、经过校验的 HTTP(S) 端点。优先保留目标端点已有密钥，不向渲染层返回明文。跨来源沿用密钥前，界面必须请求明确确认；取消则保留原端点及密钥。原凭据仍可供其他配置模型使用，自定义服务商元数据不包含密钥。

围栏代码着色通过转义文本元素渲染令牌切片，不注入 HTML；未知语言和超大内容回退纯文本。模态编辑命令复用已有保存、路径选择、版本校验及关闭保护；明确强制关闭不会保存草稿。复制操作仅将用户选中的文本写入现有系统剪贴板通道。不新增原生命令、文件授权、网络来源或能力。

新本地终端读取已登记的系统及用户可执行搜索路径，合并进子进程环境，不改动父进程环境，也不执行脚本获取路径。继承的自定义目录保留优先级，不增加文件访问授权，不改变远程环境。

## 补全与市场请求

新增 `shell_complete` 命令只接受已知 shell 标识、绝对工作目录、受长度限制的普通补全文本与有效光标偏移。内部固定脚本通过环境数据接收输入，启动前拒绝执行语法；查询不进入活动终端。子进程时长及输出受限、标准输入关闭、窗口隐藏，丢弃请求时终止子进程。远端面板不会查询本地 shell。这条只读发现路径不增加文件写入授权、能力或 CSP 例外，补全文本仍在诊断中脱敏。

现有市场命令现遵循系统代理，保持端点白名单、重定向约束与证书校验。索引与描述正文受大小限制，描述请求采用受限并发与总截止时间；列表读取固定到索引版本，切换仓库使旧界面响应失效。安装的外部技能仍默认未信任。共享资源切换入口引用原有领域身份与关闭保护路径，不重建活动资源，也不改变授权。

只读命令 `history_page` 接收有界页大小、白名单内的来源／排序值，以及长度受限的键集游标。查询片段只来自内部白名单，游标值始终通过参数绑定。返回值仅含元数据，不提供路径、脚本或远程请求入口。诊断只记录数量、是否携带游标、结果及独立的锁等待／查询耗时，不记录游标值或内容。混合展示在同一视图中移动既有宿主，不增加内容解释、文件授权、能力、进程归属或审批路径。经过校验的布局引用不能自行重新打开文件或启动进程。

文件属性和操作复用独立于终端及传输任务的已认证文件通道，最多保留 32 个空闲通道，每个配置最多两个；空闲达到 60 秒的通道不再复用。绑定包含已保存的端点、选项、密码摘要及临时认证版本。配置编辑、删除、代理变更或清除认证使缓存失效，迟到的操作不能重新放回旧通道。网络操作及清理不持有连接池锁。复用通道读取失败时最多重新连接一次，修改操作绝不自动重放。新通道仍执行主机信任和认证校验，不新增 IPC、文件授权、能力或网络来源；诊断仅记录复用、结果及耗时，不记录路径、内容或凭据。

已保存跳板引用由后端从既有连接数据库解析，检测循环并限制为八层，解析后的凭据不序列化到渲染层。每层先验证自己的主机指纹再认证，目标握手仍在转发通道内加密。内部回环套接字对只接受预先连接的对应端，在转发前关闭监听；双向缓冲有界。目标连接的所有权负责取消整条转发链，配置或认证变化使缓存通道和依赖转发失效。系统客户端仅接收非敏感临时配置，终端读取器结束时删除。链路解析不新增能力、文件授权或内容来源，不放宽主机信任。输入恢复仅向既有终端解析器写入固定模式复位，不写入远程 shell；诊断只包含模式标记，不包含按键内容。

后端每次握手前，在当前支持的算法中优先使用该端点已有信任记录的主机密钥类型，各组保留原有相对顺序。名称、哈希名称及显式端口由信任库匹配；RSA 签名算法共用记录中的 RSA 密钥身份。其余受支持算法保持原有顺序，协商后的密钥仍须在认证前通过既有严格比对；其他密钥类型不能绕过已存在的不匹配，也不会自动写入信任记录。诊断仅记录协商算法及是否优先采用已知密钥类型，不含密钥内容或凭据。单元及隔离多密钥协议测试覆盖端点匹配、未知主机、未变化的可信密钥与真实密钥变更。

服务交互认证为既有认证命令增加挑战通道，新增回答和取消命令，绑定调用窗口及请求标识符。后端重新加载已保存端点和链路，以认证版本绑定完成结果，保留连接前再次校验链路。最多同时 16 个请求，每个请求限时五分钟，每轮回答 90 秒，最多 32 轮、每轮 16 个字段；说明、标签及回答都有字节上限。未知主机密钥必须显式确认当前连接的确切指纹，指纹不匹配时不进入认证。远端提示以纯文本渲染。前后端诊断脱敏全部回答字段，回答不缓存、不写入连接配置、不用于重连重放。协议调用期间的临时回答缓冲由认证库持有。

最多保留 64 条临时认证记录。交互认证记录持有已认证连接，文件与监控共享限时十秒的操作锁和五秒网络超时；转发及传输任务不能克隆该连接或修改其阻塞模式。修改连接、清除认证、修改代理以及依赖终端关闭时使其失效，在缓存锁外执行关闭。取消会唤醒等待中的挑战并阻止保留已取消结果。网络操作不持有认证注册表或缓存锁。不增加 CSP 来源、文件授权或终端输入路径。单元、浏览器及隔离协议测试覆盖窗口及轮次校验、边界、取消、信任、并发复用和回答脱敏。

端点凭据按端点绑定，保留的连接及进行中的完成校验按完整链路绑定；展开跳板不会使该端点的凭据失效，也不会撤销其独立服务连接。最多保留最近 64 条完成记录，仅含请求及窗口标识、连接标识和版本，供迟到取消准确撤销已发布版本；移出活动注册表与发布完成记录保持原子性。调用认证方法及尝试后续密钥前检查取消状态。子系统失败后可以重新打开子系统，或打开空通道探测连接健康，不重放文件操作或远程命令；整条连接丢失时仍要求重新认证。
